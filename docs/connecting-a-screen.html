Connecting a Screen

Two different jobs, easy to conflate: pairing a screen that’s already running the Fortu Player, and installing the Fortu Player on a device for the first time. Most days you want the first one.

Most common

Pair a screen

It’s already running Fortu Player and showing a code. Takes under a minute.

 First time only

Set up new hardware

Fresh Android device, nothing installed yet. Ten minutes, done once per screen.

Pairing a screen

If the screen is already powered on and showing a code, this is all you need.

  1. Power the screen on and let it start up. It shows a 6-character code — deliberately drawn from letters and numbers that can’t be confused for one another, since it’s meant to be read off a television from across a room. Underneath the code, the screen also names the server it’s talking to. If pairing ever seems stuck, that line is the first thing to check — it's almost always the screen and the CMS pointed at different servers.
  2. In the CMS, go to Devices → Add screen, type the code, and give it a name and location.
  3. The screen picks up its credentials within about 5 seconds and moves to an idle card. Assign it a playlist and it starts playing within 30 seconds — sooner in most cases.
Note

If a screen was ever removed or unpaired from the CMS, it notices on its own and falls back to showing a fresh code — nothing needs to be done to the hardware itself. Just repeat the steps above with the new code.

Setting up new hardware

~10 min

For a device that has never run Fortu Player before. Once this is done, the screen behaves exactly like the pairing flow above — you only do this once per screen.

1. Get the app onto the device

Whichever is easiest for the hardware in front of you:

  1. Over USB, from a computer — on the device, go to Settings → About → tap Build number seven times to unlock Developer options, then Developer options → enable USB debugging. Plug it in, accept the prompt on the device, then: 
    adb install -r fortu-player.apk
  2. Without a cable — put the APK on a USB stick or in cloud storage, open it from the device’s file manager, and allow “install from unknown sources” when it asks.

2. Decide how locked-down it needs to be

A plain install still keeps the screen awake and hides the system bars, but someone could press Home and leave the app. Three levels, weakest to strongest:

Basic

Screen pinning

Works on any device, nothing to set up. Settings → Security → App pinning. Stops accidents, not a determined person.

Stronger

Make it the launcher

The screen boots straight into Fortu Player and Home returns to it. Right for hardware dedicated to signage — not your own phone, which would also start asking to become its launcher.

Recommended

Device Owner mode

Genuinely cannot be exited, disables the lock screen, and is what makes silent updates and auto-restart-after-power-cut possible. The real answer for any screen you control. Steps below.

3. Device Owner setup (recommended)

Before you start

The device must be factory-reset with no Google account signed in. Android refuses to grant this otherwise, with no way around it short of resetting again — so it has to happen before anything else, not after.

  1. Factory reset the device — Settings → System → Reset → Erase all data.
  2. Walk through setup and skip the Google account step. Skip wifi too if it's offered, then add it from Settings afterwards — some setup wizards quietly add an account the moment they're online.
  3. Enable Developer options and USB debugging (Settings → About → tap Build number ×7), then install the app and grant it ownership: 
    adb install -r fortu-player.apk
adb shell dpm set-device-owner \
  com.fortu.player/com.fortu.player.kiosk.DeviceAdminReceiver
    Expect Success: Device owner set to package com.fortu.player. If it refuses with “there are already some accounts on the device,” one slipped in during setup — factory reset and redo the previous step.
  4. Launch the app. It applies everything on first run: locks itself to the foreground, disables the lock screen, keeps the screen on, and makes itself the device's launcher.
  5. Pair it using the code it shows, same as the flow at the top of this page.
  6. Verify it took. Long-press anywhere on the screen for the diagnostics overlay — it should read device owner (full kiosk). If it says not owner (screen pinning only), the ownership step didn't succeed.
  7. Reboot the device once and confirm it comes back into the loop on its own, with nobody touching it.
Note

Device Owner mode can't be removed with a plain adb command once it's set — recovering the device for something else later means a factory reset. Worth knowing before provisioning hardware you might need back.

Orientation

Set per screen in the CMS, not baked into the install — the same app serves portrait totems and landscape panels. New screens default to portrait. Change it from the screen's page in the CMS and it takes effect on the screen's next check-in, no reinstall needed.

If something looks wrong

The screen is black, not showing a code or content

This shouldn't happen by design — an unpaired, revoked, or disconnected screen is built to always show a visible code rather than go black, specifically so it can be diagnosed from across a room. A genuinely black screen usually means power or the device itself, not the pairing.

Pairing seems stuck

Check the server address printed under the code on the screen against the CMS you're typing the code into — a screen pointed at a different server will show a valid code that can never be claimed from the wrong CMS.

How do I check what a screen thinks is going on?

Long-press anywhere on the screen. A diagnostics overlay shows its name, which server it's using, the current content version, how much it has cached, and the last error it saw — the same information you'd otherwise need a laptop and a cable to see.
